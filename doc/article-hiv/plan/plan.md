# Plan

## Brief

- 目标读者：小红书用户（对 HIV 健康管理感兴趣的患者、家属、医疗从业者、对科技健康工具感兴趣的普通读者）
- 目标语言：中文（跟随源语言）
- 文章类型：briefing（决策摘要 · 给忙人快速判断 · 小红书快阅风格）
- 信息保留比例：50%（标配 40-60%，用户选 briefing·50%，结论先行，精华提炼，视觉卡片为主载体）
- 必须保留：三大核心技术（RAG/知识图谱/症状网络）的定义与价值；四大功能模块；关键数字（89篇文献/2806节点/3712关系边/27个症状/19种关系类型）；免责声明；复旦大学出处
- 可删减：技术架构细节（Serverless架构段落可精简）；GraphicalLasso技术名词解释（视觉卡展示即可）
- 语气：温柔科普 · 有人情味 · 不端着 · 让人安心读完
- 主要观点：① AI健康工具最重要的是"可信"而非"能说"；② 三项技术组合形成完整的"知识底座"；③ 技术最终服务于具体的人
- 阅读目标：读完能理解这个小程序的核心价值与使用方式，感受到"这是一个靠谱的、有温度的健康工具"
- 版式宽度：regular
- TOC：开
- 配图策略：none（靠 Raw 视觉卡片 + SVG 图解替代，离线可用）
- 封面：开。构图想法：模板 A（上字下图）。视觉主体：SVG 节点网络图（模拟症状网络/知识图谱节点连接），暖橙圆形节点+连线，andy主题奶油底。文字层：大圆体标题"循证健康管理" + 副题"复旦团队 × 微信小程序" + 小标签"艾滋病健康管理"。

## Outline

- Hero：标题「把"循证健康管理"装进微信」+ 副题「每个回答都有据可查，每个症状都在图谱里找到关联」+ meta（复旦大学护理学院 · 2024）
- Lead：导语——HIV患者面临的三大困扰（用药/症状/信息），这个小程序如何回应
- Summary：不单独放；核心价值在 Hero + Lead 已点明

### Sections

1. **01-problem** 患者困境：为什么需要这个工具？
   - 保留信息：三类困扰（用药复杂/症状繁多/信息混乱）；普通AI"一本正经地胡说"；"可信比能说重要"
   - 组件：Section正文 + Quote（"可信比能说更重要"）
   - 是否需要Raw：是。三卡片并排展示三大困扰（暖橙圆角卡，andy风格）

2. **02-rag** 核心技术①：RAG让AI"有据可查"
   - 保留信息：RAG概念；5步问答链路（意图识别→图谱检索→知识库检索→循证生成→溯源展示）；89篇权威文献；证据等级A/B/C；"还告诉你答案从哪来"
   - 组件：Section正文
   - 是否需要Raw：是。5步流程图（圆角步骤卡，从上到下或左到右，andy风格）

3. **03-kg** 核心技术②：知识图谱把知识连成网
   - 保留信息：三元组定义+示例（HIV感染→症状→发热等）；2806节点/3712边/19种关系类型；"可查询、可推理、可视化"
   - 组件：Section正文
   - 是否需要Raw：是。SVG小型三元组示意图（3个节点，带箭头和关系标签，andy节点色）

4. **04-sn** 核心技术③：症状网络揭示"症状如何相伴"
   - 保留信息：数据驱动vs文献语义；GraphicalLasso；27个症状；疲乏-焦虑-失眠关联示例；预警功能
   - 组件：Section正文
   - 是否需要Raw：是。小型症状关联示意图（圆形节点，连线粗细表示关联强度）

5. **05-features** 四大功能一图看懂
   - 保留信息：健康问答（溯源/思考过程/转人工）；知识-症状图谱（交互/联动）；健康管理（用药/复诊/运动/热量）；症状自查（分级建议/一键120）
   - 组件：Section正文
   - 是否需要Raw：是。2×2功能卡片网格（大圆角，每卡有图标+标题+关键特性列表，andy暖橙）

6. **06-closing** 写在最后
   - 保留信息："可信比能说更重要"；三技术结合的价值总结；"技术的价值最终要落到一个个具体的人身上"；免责声明
   - 组件：Section正文 + Quote（收束语）
   - 是否需要Raw：否（留白收束，轻盈）

- 结尾方式：留白收束 + 免责声明（小字柔和展示）

## Theme

- 选定主题：andy
- 理由：文章面向健康类受众，小红书平台风格需要温柔、亲和、治愈感；andy主题暖奶油+南瓜橙+大圆角完美匹配健康/wellness内容的情绪需求，降低HIV话题的压迫感，让读者安心浏览
- 与源材料的冲突：源材料偏技术科普，andy偏治愈亲和。处理方式：技术概念用可视化卡片+步骤图降低阅读门槛，保持技术准确性的同时增加温度感
- 当前信息密度下的表现建议：80% visual-essay，Raw卡片多用（每个技术Section配一个图解），正文精简，大留白，圆圈章节号标注关键数字

## Assets

- 策略：none
- 说明：不使用外部图片（离线可用），全靠内联SVG + CSS Raw块表达视觉内容，andy圆角卡片+暖橙节点图解替代原文截图
